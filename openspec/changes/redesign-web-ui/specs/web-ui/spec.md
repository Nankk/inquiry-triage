## ADDED Requirements

### Requirement: 段のスジ
承認キュー画面の一覧の各項目と詳細、追跡画面は、問い合わせ 1 件の段（分類 → 担当 → 検査 → キュー）を等間隔の 4 点を結ぶ一本の線（スジ）として描かなければならない（SHALL）。本番は実線、影は破線で担当から始まる。失敗した段と「人が直接対応」は線がその段で止まり、終端記号が付く。線の色と太さは緊急度（high / normal / low）の 3 段で、全画面で同じ。

#### Scenario: 影つきの項目
- **WHEN** 影つきで run した INQ-001 を一覧で見る
- **THEN** 実線が 4 点を結び、その下に破線が担当の点からキューの点まで並走する。分類の点に破線は無い

#### Scenario: 人が直接対応
- **WHEN** INQ-005（other）を一覧で見る
- **THEN** 線は分類の点で止まり、終端記号が付く。担当・検査・キューの点は結ばれない

#### Scenario: 緊急度で太さと色が変わる
- **WHEN** INQ-001（high）、INQ-004（normal）、INQ-003（low）を並べて見る
- **THEN** 3 本の線の太さと色が緊急度の 3 段で異なり、一覧と詳細と追跡画面で同じ対応になる

## MODIFIED Requirements

### Requirement: 追跡画面
画面は問い合わせ 1 件の段（route → retrieve → draft → review / verify → enqueue、影があれば shadow_*）を等間隔の駅として一本の線で示し、各段の所要時間（elapsed_ms）は位置ではなく点の下の数字で添えなければならない（SHALL）。本番と影の返信案・レビュー判定・警告は左右に並べて見せる。問い合わせ本文は返信案の比較の上に表示する。

#### Scenario: 左右比較
- **WHEN** 影つきで run した INQ-001 を開く
- **THEN** 左に本番（billing_specialist）の返信案と flag の理由、右に影（billing_specialist_v2）の返信案と pass が並ぶ

#### Scenario: 所要時間は数字で読む
- **WHEN** 担当の段だけ数秒かかった実モデルの記録（INQ-001）を開く
- **THEN** 4 点の間隔は等しいままで、担当の点の下の数字だけが大きい。fixture リプレイの数ミリ秒の記録でも同じ間隔で描かれる
